🔄 核心请求流程
1
用户发消息 → Streamlit 前端 → POST /chat (session_id + messages)
2
FastAPI 接收 → chat_with_tools() → 加载 Redis 会话 → tiktoken Token 裁剪
3
LangGraph 启动 → graph.ainvoke(initial_state) → 创建 Supervisor 节点
4
Supervisor 路由 → 硬规则匹配 (30+ 关键词) or LLM 语义分类 (DeepSeek) → 选择 Agent
5
Agent 执行 → 调用专属工具集 → 生成回复 (或继续循环，最多 8 次)
6
结果返回 → final_reply → 保存会话到 Redis → 返回前端展示
7
LangSmith 追踪 → 全程 @traceable 埋点 → 可视化分析性能瓶颈

💡 性能洞察

硬规则路由比 LLM 分类快约 1s（无 LLM 调用开销）。LLM 调用占总耗时约 70%，是主要优化方向。可通过并行工具调用、知识库缓存、意图分类模型轻量化来降低延迟。
